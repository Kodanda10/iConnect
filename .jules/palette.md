## 2024-12-14 - Custom Calendar Accessibility Patterns
**Learning:** Custom calendar components built with `div`s and `button`s require extensive ARIA attributes to be usable by screen readers. A standard `role="button"` for a day cell is insufficient if it represents a selectable option. Furthermore, using `aria-selected` is invalid on `role="button"`; instead, `aria-pressed` must be used. Complex toggles for Month/Year selection need proper dropdown semantics (`aria-haspopup`, `aria-expanded`, `role="listbox"`, `role="option"`). Finally, day labels must be fully descriptive strings (e.g. "1 January 2024") rather than just the number, so users hear the full context.
**Action:** When auditing or creating custom interactive components like calendars, strictly apply WAI-ARIA authoring practices. For date selections mapped to buttons, use `aria-pressed` for the selected state and `aria-current="date"` for today's date.
