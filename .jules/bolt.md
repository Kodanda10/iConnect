## 2024-05-20 - Date Parsing in Hot Loops
**Learning:** In Cloud Functions with potentially thousands of iterations (like iterating over all constituents), repeated `new Date(string)` calls are significantly expensive.
**Action:** When comparing dates in a loop, parse the target date once outside the loop. If the source data is a string (e.g. YYYY-MM-DD), consider parsing it once into lightweight components (month/day integers) or ensure the `new Date()` call happens only once per item, not multiple times for different comparisons (e.g. against today vs tomorrow).

## 2025-04-05 - String Split vs CharCodeAt for Parsing YYYY-MM-DD in Hot Loops
**Learning:** In `functions/src/generateTasksForDateRange.ts`, `String.prototype.split('-')` creates an array of substrings which involves significant string and array object allocations. In highly iterative loops, using `charCodeAt` to manually parse standard `YYYY-MM-DD` strings avoids these allocations entirely, yielding up to an 8x speedup.
**Action:** Whenever parsing standard fixed-format string structures (like `YYYY-MM-DD`) in performance-critical hot loops, prefer using `length` checks followed by `.charCodeAt(index)` to extract characters as ASCII integers. Always remember to validate the bounds (ASCII 48-57) to guarantee inputs are indeed digits before mathematical operations, and provide a fallback logic (like `.split`) for non-standard lengths.
